# CherenkovBench (iOS)

A minimal UIKit host that runs `cherenkov-bench render`/`measure` on an
iPhone's GPU. iOS cannot run a command-line binary, so the CLI is
wrapped in an app that calls `cherenkov_bench_run` — the same entry
point `main` forwards to — once per argument list. The screen shows
the run in progress, then one line per run with its exit code; the
app stays open unless launched with `--exit-after-run`.

The Xcode project is generated by [XcodeGen](https://github.com/yonsm/XcodeGen)
from `project.yml`; nothing generated is checked in.

## Build

    # Rust static library (from the repo root). If the skia-bindings
    # prebuilt download for aarch64-apple-ios fails, drop `skia-metal`.
    cargo build --locked --release --target aarch64-apple-ios \
        -p cherenkov-bench --lib \
        --features cherenkov,vello-hybrid,vello-classic,skia-metal

    cd bench/ios
    xcodegen generate
    xcodebuild -project CherenkovBench.xcodeproj -scheme CherenkovBench \
        -sdk iphoneos -configuration Release -derivedDataPath build \
        CODE_SIGNING_ALLOWED=NO build

A fresh Xcode may report "iOS is not installed" — the SDK ships but
device support is a separate component:

    xcodebuild -downloadPlatform iOS

The unsigned app lands in
`build/Build/Products/Release-iphoneos/CherenkovBench.app`.

## Simulator

Build the Rust library for `aarch64-apple-ios-sim` first:

    cargo build --locked --release --target aarch64-apple-ios-sim \
        -p cherenkov-bench --lib \
        --features cherenkov,vello-hybrid,vello-classic,skia-metal

Then the app. `-destination` is required — `-sdk iphonesimulator` alone
resolves to "Any iOS Simulator Device", a universal arm64+x86_64 build
that fails to link because `libcherenkov_bench.a` is arm64-only. The
product lands under `Release-iphonesimulator`:

    xcodebuild -project CherenkovBench.xcodeproj -scheme CherenkovBench \
        -sdk iphonesimulator \
        -destination 'platform=iOS Simulator,name=iPhone 17' \
        -configuration Release -derivedDataPath build \
        CODE_SIGNING_ALLOWED=NO build

The simulator's paravirtual GPU is weaker than a real device (no
`TIMESTAMP_QUERY` or `INDIRECT_EXECUTION`, so `gpu_seconds` are absent
and `vello-classic` cannot run there) but it exercises the whole
harness end to end. Boot a simulator (`open -a Simulator`, or
`xcrun simctl boot 'iPhone 17'`), then:

    xcrun simctl install booted \
        build/Build/Products/Release-iphonesimulator/CherenkovBench.app

Push the inputs into the app's Documents. `simctl` has no file copy,
so write the container directory directly —
`get_app_container ... data` returns its sandbox home:

    DATA=$(xcrun simctl get_app_container booted dev.cherenkov.bench data)
    cp -R ../../scenes "$DATA/Documents/scenes"
    # bench-args.json: this launch's run id, then one argument list per
    # run — a 30-frame measure of the map scene on the cherenkov backend:
    cat > "$DATA/Documents/bench-args.json" <<'EOF'
    {
        "run_id": "6f1c0a9e4b27",
        "runs": [
            ["engines"],
            ["measure", "--engine", "cherenkov", "--scene",
             "Documents/scenes/perf/map", "--frames", "30", "--warmup",
             "5", "--out", "Documents/out/measure-cherenkov-map.json"]
        ]
    }
    EOF

    xcrun simctl launch booted dev.cherenkov.bench

    # pull the report and the captured stderr/stdout log back
    cp -R "$DATA/Documents/out" ./out
    cat ./out/done.json ./out/measure-cherenkov-map.json ./out/run-1.log

## Sign

The .app ships unsigned. To run it on a device it needs a development
signature plus a provisioning profile whose app ID covers
`dev.cherenkov.bench` (a wildcard profile works) and that lists the
device:

    cp ios-dev.mobileprovision CherenkovBench.app/embedded.mobileprovision

    # lift the entitlements out of the profile so codesign keeps them
    security cms -D -i ios-dev.mobileprovision > /tmp/profile.plist
    /usr/libexec/PlistBuddy -x -c 'Print :Entitlements' /tmp/profile.plist \
        > /tmp/entitlements.plist

    codesign -f -s "Apple Development: Your Name (TEAMID)" \
        --entitlements /tmp/entitlements.plist CherenkovBench.app

## Install and drive

    # install (or `ideviceinstaller -i CherenkovBench.app`)
    xcrun devicectl device install app --device <udid> CherenkovBench.app

    # push inputs: {"run_id", "runs"} where runs is the argument lists
    # (no program name; argv[0] is inserted by the app), plus the scene
    # corpus under scenes/ — generated, not committed, so
    # `python3 scenes/tools/generate.py` first.
    # Documents/ is shared (UIFileSharingEnabled), so Finder's device
    # Files tab or `ifuse --documents dev.cherenkov.bench` also work.
    xcrun devicectl device copy to --device <udid> \
        --domain-type appDataContainer \
        --domain-identifier dev.cherenkov.bench \
        --source bench-args.json --destination Documents/bench-args.json
    xcrun devicectl device copy to --device <udid> \
        --domain-type appDataContainer \
        --domain-identifier dev.cherenkov.bench \
        --source scenes --destination Documents/scenes

A `bench-args.json` that measures one scene on every compiled-in
engine looks like:

    {
        "run_id": "chart-engines",
        "runs": [
            ["engines"],
            ["measure", "--engine", "cherenkov", "--scene",
             "Documents/scenes/perf/chart", "--frames", "120", "--warmup",
             "10", "--rate", "60", "--out", "Documents/out/measure-cherenkov-chart.json"],
            ["render", "--engine", "cherenkov", "--scene",
             "Documents/scenes/perf/chart", "--out",
             "Documents/out/render-cherenkov-chart.json"]
        ]
    }

`measure --native` and `capacity` run through the same file — the
argument lists go verbatim to `cherenkov_bench_run`, so every CLI flag
is reachable. On a device host `--native` carries the window's pixel
size (the bench renders offscreen), and `--rate` the panel refresh. An
iPad Pro M4 (2752×2064 at 120 Hz) capacity sweep over the perf corpus:

    {
        "run_id": "ipad-capacity",
        "runs": [
            ["capacity", "--engine", "cherenkov", "--engine", "vello-hybrid",
             "--corpus", "Documents/scenes/perf", "--frames", "120",
             "--warmup", "10", "--budget-ms", "8.333",
             "--out-dir", "Documents/out"],
            ["measure", "--engine", "cherenkov", "--scene",
             "Documents/scenes/perf/chart", "--native", "2752x2064",
             "--rate", "120", "--frames", "120", "--warmup", "10",
             "--out", "Documents/out/measure-cherenkov-chart-native.json"]
        ]
    }

Launch and keep it in the foreground — iOS forbids GPU work in the
background. The app disables the idle timer and drops screen brightness
to 0 for the whole run, then restores both. It reads
`Documents/bench-args.json` (`run_id` plus `runs`) and writes
`Documents/thermal.json` (`state` and that `run_id`) before touching
`out`. A serious or critical state skips the measurement. It then
empties `Documents/out` and `chdir`s to the app's home directory (an
app launches with cwd `/`), so relative `Documents/...` paths in the
argument lists resolve as written and everything left in `out` belongs
to that launch. Each argument list runs through `cherenkov_bench_run`
on a background thread with fds 1 and 2 redirected to
`Documents/out/run-<n>.log` (the suite's tracing goes to stderr); when
the last one returns the app writes `Documents/out/done.json` (the
same `run_id`, and each run's args, exit code, and thermal state words
before and after) and stays open showing the same summary on screen.
`done.json` remains
the on-disk completion record. With `--exit-after-run`, the app restores
brightness and exits with the first failed run's code (zero on success).
`devicectl --console` then waits for process completion without polling:

    xcrun devicectl device process launch --console --device <udid> \
        dev.cherenkov.bench --exit-after-run

    xcrun devicectl device process launch --device <udid> dev.cherenkov.bench

    # pull results
    xcrun devicectl device copy from --device <udid> \
        --domain-type appDataContainer \
        --domain-identifier dev.cherenkov.bench \
        --source Documents/out --destination ./out

Logs go to `os.Logger` subsystem `dev.cherenkov` (category `bench`):

    xcrun devicectl device console --device <udid> | grep dev.cherenkov
